# CLAUDE.md — working on Argon

Argon is an open-source AI agent made of:

- a TypeScript **core** (engine + local HTTP/WebSocket server, built on Pi: `@mariozechner/pi-ai`, `@mariozechner/pi-agent-core`);
- a **Rust CLI** (`rust/cli`, the `argon` binary): a full-screen terminal client of the core;
- a vanilla-JS **GUI** (`gui/`) served by the core;
- a **Tauri** desktop shell (`rust/desktop`) that starts the core and shows the GUI.

```
argon (Rust CLI) ──HTTP/WS──┐
                            ├── core: `argon-core serve` (Node + Pi) ── ~/.argon (sessions, settings, usage…)
Argon.exe (Tauri) ─webview──┘
```

The desktop app starts the core with `serve --advertise` (writes `~/.argon/core.json`); the CLI reuses it when it answers `/api/ping`, otherwise it starts a private core. A core started by a client exits when that client closes its stdin.

## Commands

```bash
npm run build        # tsc → dist/ (the GUI has no build step)
npm test             # node --test test/*.test.mjs — fake model, no network; must stay green
npm run cli          # build the core, then run the Rust CLI from source (cargo run -p argon-cli)
npm run desktop      # build the core, then `tauri dev` for the desktop app
npm run dist         # core + staged runtime + release CLI → Tauri NSIS installer (rust/target/release/bundle/nsis/)
cd rust && cargo test -p argon-cli
node test/harness/tui-harness.mjs <outDir>   # legacy TypeScript TUI in headless xterm (still used for `npm start`)
```

Testing the Rust clients without network or touching `~/.argon`: point them at the fake-model core.

```bash
ARGON_HOME=/tmp/argon-test ARGON_NODE=node ARGON_CORE_ENTRY=test/fixtures/faux-core.mjs rust/target/debug/argon -p "Explain this project with a sub-agent"
```

(`ARGON_FAUX_MODE=ask` makes it request approvals; the same variables work for `argon-desktop`. Add `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9336` to inspect the desktop webview over CDP.)

Always run `npm run build && npm test` (and `cargo build` for Rust changes) before committing.

## Conventions

- ESM TypeScript (`module: NodeNext`): import local files with the `.js` extension.
- User-facing strings are bilingual: `T("italiano", "English")` in the TS CLI, `self.t(it, en)` in the Rust CLI (language = `settings.cli.language`), `tt(it, en)` / `t(key)` in the GUI (language = `settings.general.language`).
- All clients share `~/.argon` (`ARGON_HOME` overrides it). Anything cached in memory must tolerate another process writing the same file (see config.ts, sessions.ts, usage.ts).
- Settings: add the field to the `Settings` type **and** `DEFAULT_SETTINGS`; `cli.*` is CLI-only, everything else is shared. Usage limits are always shared.
- The Rust CLI holds no agent logic: new features go into the core (and its HTTP API), then into the clients. Sessions created by the CLI pass `origin: "cli"`; list them with `GET /sessions?origin=all`.
- The CLI creates its session on the first message (no empty sessions).
- GUI: no framework, no bundler. Render with template strings + `esc()` for every interpolated value. Raw HTML from the model is escaped in `md()`; keep the CSP in server.ts strict.
- GUI transcript updates go through `reconcile()` (only changed blocks are replaced) so animations don't restart while streaming — don't replace it with `innerHTML`.
- Native `<select>` elements are upgraded automatically to M3 menus by `lib.js` (MutationObserver); dispatch `change` on the select when setting values programmatically.
- Desktop bridge: the GUI only uses `window.argonDesktop` (pickFolder, setTheme, setZoom, openExternal). In Tauri it is injected by `BRIDGE` in rust/desktop/src/main.rs; every command must be listed in `build.rs` (AppManifest) **and** allowed in `capabilities/default.json`, because the GUI is a remote origin.
- Nested corners are concentric: inner radius = outer radius − padding (see `.send`, `.env-ico`, `.limit-preview .lim`).
- Usage events from sub-agents carry `agent`; housekeeping calls use `"title"` / `"compaction"`. Totals always include them.
- Security: never log or send credentials; the API requires the `X-Argon-Token` header (favicons accept `?t=`, the WebSocket `?t=`); writes outside an environment must keep going through the sandbox check.

## Gotchas

- Shell heredocs/`node -e` turn `\\` into `\` and `"\n"` into real newlines inside generated code — edit source files with an editor tool, not inline scripts, when they contain regexes or escapes.
- Windows + `x86_64-pc-windows-gnu`: crates using `windows-link` need MinGW binutils (`as`, `dlltool`) on PATH — `scripts/rust-env.mjs` / `rust/env.sh` add WinLibs or MSYS2. With the MSVC toolchain nothing is needed.
- Pi's Anthropic provider only knows adaptive thinking for 4.6/4.7 model ids; `adaptiveThinkingPatch` (effort.ts) upgrades newer Claude ids through `onPayload`.
- `where rg` on Windows prints to stderr when ripgrep is missing: child processes used by the TUI must not inherit stderr.
- The core prints exactly one `ARGON_READY {json}` line on stdout; clients parse it, so don't log to stdout before it in `serve`.
